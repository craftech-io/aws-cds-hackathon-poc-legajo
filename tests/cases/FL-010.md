# FL-010 · Carga por link rechazada

> Caso de QA escrito antes de construir (WP-45). WP-42 lo actualiza con lo que cambie al construir. Fuente: `docs/flows-catalog.md` FL-010.

| Campo | Valor |
|---|---|
| Área | B · Pedido inicial y WhatsApp del importador |
| Actores · canal | Importador · link de carga |
| Reglas | POST prefirmado con `content-length-range`, `Content-Type` y clave exacta; validación `%PDF-` en el intake |
| Depende del modelo | No |
| Pruebas | U `public-web/upload.test.ts` · UI `public-upload.spec.ts` · SR `SC-07/4..6` |

## Entrada

Link de carga vigente de `op-4471` (SR: el del paso `SC-07/1`) y cuatro variantes:

- (a) token vencido (`link.expire`);
- (b) token de otra operación usado para una clave que no es la suya (U: objeto con la clave de otro token);
- (c) archivo que no es PDF: (c1) `Content-Type` distinto de `application/pdf`; (c2) `application/pdf` declarado pero sin `%PDF-`;
- (d) PDF de más de 10 MB.

## Pasos

1. (a) Abrir `/u/<token>` con el token vencido.
2. (b) Hacer llegar a `DocumentIntake` un objeto cuya clave no pertenece al token.
3. (c1), (c2) y (d) Subir con el prefirmado vigente.
4. `op.settle`.

## Resultado esperado

1. (a) Página de link vencido sin número de operación ni documentos; métrica `UploadLinkInvalid` + 1 (sin fila de bitácora por intento, `docs/architecture.md` §11).
2. (b) `DocumentIntake` descarta la clave ajena y lo audita (`DENY UPLOAD_*` con el motivo de clave).
3. (c1) y (d) S3 rechaza el POST por las condiciones de la política (tipo o tamaño): no hay objeto en `Uploads`.
4. (c2) El intake rechaza por `%PDF-` y lo audita (`DENY UPLOAD_*` con el motivo de tipo).
5. En todas: ningún `DocumentVersion` nuevo, el certificado sigue `MISSING` y no hay turno `UPLOAD_COMPLETED` por esos archivos.

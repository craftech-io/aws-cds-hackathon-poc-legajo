# FL-108 · Cerrar sesión

> Caso de QA escrito antes de construir (WP-53, ola 3, etapa A1). WP-42 lo actualiza con lo que cambie al construir. Fuente: `docs/flows-catalog.md` FL-108; copy en `docs/landing-spec.md` §8.7.

| Campo | Valor |
|---|---|
| Área | L · Alta pública, cuenta de invitado y leads |
| Actores · canal | Invitado · consola (menú de cuenta → "Cerrar sesión" / "Sign out") |
| Reglas | `RevokeToken` del refresh token; tokens solo en `sessionStorage`; cerrar sesión no borra el mundo ni el lead |
| Depende del modelo | No |
| Pruebas | U `views/auth/session.test.ts` · UI `auth.spec.ts` · SR `SC-26/7` |

## Entrada

- Una sesión `GUEST` pública con mundo `READY` (`UI`: firmada con la clave efímera; `SR`: la cuenta del buzón `a` después de `SC-26/6`).
- `U`: el módulo de sesión con un refresco en curso y un temporizador de refresco programado.

## Pasos

1. Abrir el menú de cuenta y tocar "Cerrar sesión".
2. Intentar renovar con el refresh token revocado.
3. Ingresar de nuevo con la misma cuenta mientras el mundo no venció.
4. `SR` `SC-26/7`: "Cerrar sesión" → `/?signedOut=1` → renovación con el refresh token guardado por el paso → `lead.inspect(a)`.

## Resultado esperado

1. `RevokeToken` del refresh token; `sessionStorage` sin tokens; los refrescos en curso y programados se cancelan.
2. La web va a `/?signedOut=1` y la landing muestra el aviso descartable `login.notices.signedOut` ("Cerraste sesión").
3. El refresh token revocado no renueva.
4. El mundo y el lead siguen intactos: el ingreso siguiente llega a `READY` sin crear otro mundo mientras no venza el TTL.
5. (`SC-26/7`) Aviso visible, renovación rechazada y `lead.inspect(a)` conserva el `firmId`.

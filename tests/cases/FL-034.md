# FL-034 · Duplicados entrantes (email y WhatsApp)

> Caso de QA escrito antes de construir (WP-45). WP-42 lo actualiza con lo que cambie al construir. Fuente: `docs/flows-catalog.md` FL-034.

| Campo | Valor |
|---|---|
| Área | C · Proveedor por email |
| Actores · canal | Canal · email, WhatsApp |
| Reglas | Idempotencia (`Runtime/IDEMP#`, 7 días) + deduplicación FIFO (`MessageDeduplicationId = eventId`) |
| Depende del modelo | No |
| Pruebas | U `channels/email/inbound.test.ts`, `channels/whatsapp/inbound.test.ts`, `worker/idempotency.test.ts` · SR `SC-15/1`, `SC-18/3` |

## Entrada

- Email: una respuesta confiable del proveedor con un PDF (`SC-15`, clon de `op-4471`), reentregada con el mismo recibo y el mismo objeto de S3 (`email.redeliver`).
- WhatsApp: un texto del importador (`SC-18`, mundo `sc18`) reenviado con el mismo `wamid` (misma clave de idempotencia).

## Pasos

1. Entregar el original; `op.settle`.
2. Reentregar el duplicado; `op.settle`.

## Resultado esperado

1. (snapshot) Exactamente un `Message IN` por original.
2. (snapshot) Email: exactamente un intake (una `DocumentVersion`) y un turno `SUPPLIER_EMAIL`.
3. (snapshot) WhatsApp: exactamente un turno `IMPORTER_MESSAGE` (o una lista `OPERATION_CHOICE` si el importador tiene dos operaciones abiertas); el duplicado no suma al contador de rate limit (FL-094).
4. (bitácora) Ninguna acción duplicada; el duplicado queda registrado como descartado por idempotencia.

## Cobertura por nivel

| Nivel | Prueba | Qué asierta con la etiqueta `[FL-034]` |
|---|---|---|
| U | `channels/email/inbound.test.ts` | Mismo `mail.messageId` y mismo `Message-ID` del MIME → un solo registro, un intake, un turno |
| U | `channels/whatsapp/inbound.test.ts` | Mismo `wamid` → descartado antes de contar para el rate limit y antes de encolar |
| U | `worker/idempotency.test.ts` | Mismo `eventId` dos veces en el worker → `IDEMP#` con `attribute_not_exists` lo procesa una vez; `inFlight` no queda desbalanceado |
| SR | `SC-15/1` | Reentrega del mismo email |
| SR | `SC-18/3` | `wamid` duplicado |

## Oráculo

No aplica: flujo determinista. Los conteos exactos corren después de `op.settle`.

## Evidencia

- Vitest filtrado por `[FL-034]`.
- `scenario-report.json` (`SC-15/1`, `SC-18/3`): conteos de mensajes, versiones y turnos antes y después del duplicado.

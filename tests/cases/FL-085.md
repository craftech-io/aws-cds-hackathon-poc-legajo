# FL-085 · Métricas con rótulos

> Caso de QA escrito antes de construir (WP-45). WP-42 lo actualiza con lo que cambie al construir. Fuente: `docs/flows-catalog.md` FL-085.

| Campo | Valor |
|---|---|
| Área | J · Consola y superficies públicas |
| Actores · canal | Despachante · consola (`/app/metrics`) |
| Reglas | Cada KPI con N, mundo de origen y rótulo (medido, agente guionado o supuesto); nunca se mezclan fuentes |
| Depende del modelo | No |
| Pruebas | U `metrics/kpis.test.ts` · UI `metrics.spec.ts` · SR `SC-20/4` |

## Entrada

- UI: mundo en memoria con `LegajoMetrics` de las tres fuentes (este mundo; lote con agente real, N = 20; lote con agente guionado, N = 200) y `Firms/SETTINGS` con la base manual desglosada.
- SR: `GLOBAL#firm-qa` recién reiniciado (plantilla `qa-min` con el fixture de métricas) y los agregados de `scripts/seed/data/manifest.json`.

## Pasos

1. Abrir `/app/metrics`; recorrer las tres pestañas; exportar CSV.
2. SR: `metrics.get` de `GLOBAL#firm-qa` y comparación con el manifest.

## Resultado esperado

1. (consola) Minutos humanos por acciones contra la base manual desglosada rotulada **supuesto**; intervenciones; % completos ≥ 72 h; % observaciones al responsable correcto (solo con agente real; con agente guionado dice "no aplica"); violaciones (0) junto a `DENY`/`DEFER` por regla; costo por legajo ("sin tarifa verificada" mientras haya tarifas provisionales); latencia p50/p95.
2. Cada KPI muestra N, mundo de origen y rótulo; ningún número mezcla fuentes.
3. El CSV exportado trae las mismas columnas de rótulo.
4. (SR) Los KPIs de `GLOBAL#firm-qa` iguales a los agregados del manifest (N, fuente y rótulo).

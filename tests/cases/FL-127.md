# FL-127 · Landing en cualquier ancho, accesible y liviana

> Caso de QA escrito antes de construir (WP-53, ola 3, etapa A1). WP-42 lo actualiza con lo que cambie al construir. Fuente: `docs/flows-catalog.md` FL-127; diseño en ADR-0016 §1 y `docs/landing-spec.md` §5.1 a §5.5 (§5.3 es la fuente única del presupuesto).

| Campo | Valor |
|---|---|
| Área | M · Landing comercial y superficies neutrales |
| Actores · canal | Visitante · web (`/`, `/signup`, `/login`, `/forgot`) |
| Reglas | Layout por ancho de §5.1; WCAG 2.2 AA; presupuesto de §5.3; chunk de landing y acceso separado de la consola; sin fuentes, scripts ni analítica de terceros; sin SDK de WAF; metadatos sin palabras de `scripts/lint/neutral-words.ts`; `robots` estático (FL-089) |
| Depende del modelo | No |
| Pruebas | U `scripts/landing/bundle-budget.test.ts` · UI `landing-layout.spec.ts`, `a11y.spec.ts` |

## Entrada

- La web construida (`npm run build -w packages/web`) y servida por el `ui-server`.
- Anchos 360, 390, 768, 1024 y 1440 px; perfil móvil 4G y CPU 4× para el presupuesto.
- `@axe-core/playwright` (dependencia de desarrollo pedida por WP-48).
- Excepción de `docs/test-plan.md` §2.1: Lighthouse sobre `poc` en la verificación post-deploy (`docs/architecture.md` §15 paso 6).

## Pasos

1. Abrir `/`, `/signup`, `/login` y `/forgot` en cada ancho; medir `scrollWidth` contra `clientWidth`.
2. Recorrer cada página solo con teclado (Tab, Enter, Espacio, ← →, Escape) y completar el alta con teclado.
3. Correr axe sobre `/`, `/signup`, `/signup/verify`, `/login`, `/forgot`, `/welcome` y el diálogo de la galería, en es y en.
4. Medir el presupuesto (LCP, CLS, peso de JS, CSS y fuente) y revisar qué recursos se descargan en `/`.
5. Revisar `title`, `description`, Open Graph, `hreflang` y `canonical`.

## Resultado esperado

1. Ningún scroll horizontal en ningún ancho; ningún texto cortado; objetivos táctiles ≥ 44 × 44 px; layout de §5.1 por ancho.
2. Foco visible con contraste ≥ 3:1, orden de foco igual al visual, enlace "Saltar al contenido" primero, el header fijo no tapa el elemento enfocado; el alta se completa solo con teclado.
3. axe sin violaciones `serious` ni `critical` en cada página y en el diálogo.
4. LCP < 2,5 s con el `h1` del hero como elemento LCP, CLS < 0,05; JS de landing + acceso ≤ 90 KB gzip en un chunk separado de la consola, CSS ≤ 35 KB y fuente ≤ 45 KB (`landing:budget`); el hero sin imagen raster; las imágenes bajo el pliegue con `loading="lazy"` y `decoding="async"`.
5. La consola no se descarga en `/` (salvo prefetch en `idle` con sesión); ninguna fuente, script ni analítica de terceros; ningún dominio ni SDK de WAF.
6. `title` y `description` es/en, Open Graph con la captura `og-card` real, `hreflang` es/en y `canonical`; ninguno contiene palabras de `scripts/lint/neutral-words.ts`.

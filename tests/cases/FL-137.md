# FL-137 · Cuenta bloqueada por el operador

> Caso de QA de `docs/flows-catalog.md` FL-137; decisión en ADR-0021 §16.

| Campo | Valor |
|---|---|
| Área | L · Alta pública, cuenta de invitado y leads |
| Actores · canal | El operador y una cuenta que abusa de la demo (invitado, personal o automatización) · terminal del operador y web (`/verify-phone`, consola) |
| Reglas | La marca `blockedAt` de `Leads/PHONE#<sub>/ACCOUNT` la ponen y la quitan solo `console:block` y `console:unblock`; gana sobre todo, también sobre la de automatización; con ella todo procedimiento responde 403 `ACCOUNT_BLOCKED` salvo `account.preferences` y `account.endPhoneSession`; ningún SMS ni código aceptado; la terminal no muestra emails |
| Depende del modelo | No |
| Pruebas | U `routers/account-blocked.test.ts`, `scripts/console/block.test.ts`, `packages/web/src/views/phone/phone-model.test.ts` |

## Entrada

- Un invitado con el celular verificado, un id token vigente y una sesión que ya pasó el código; un despachante con su estudio en el mismo estado; una cuenta con la marca de automatización.
- El conector en memoria y dobles de Cognito que solo registran las llamadas: ninguna prueba llama a AWS.
- Excepción de `docs/test-plan.md` §2.1: sin `SR` (un escenario deshabilitaría una cuenta real de Cognito).

## Pasos

1. `npm run console:block -- --stage poc --account <email>` con dos marcas `SESSION#` y un código en vuelo.
2. Con el mismo token: `account.session`, `account.usage`, `account.world`, `account.ensureWorld`, `account.setLanguage` y, para el despachante, `operations.list`.
3. Con el mismo token: `account.phoneStatus`, `account.sendPhoneCode` y `account.verifyPhoneCode`.
4. `account.preferences` y `account.endPhoneSession`.
5. Bloquear la cuenta con la marca de automatización y pedir `account.session`.
6. `npm run console:unblock -- --stage poc --account <usuario>` y repetir el paso 2.
7. Un nombre de usuario o un email sin cuenta, y argumentos de más o sin `--stage poc`.

## Resultado esperado

1. El script marca primero, después deshabilita y cierra las sesiones en Cognito y borra las tres marcas del celular; imprime el nombre de usuario y la cantidad borrada, nunca el email.
2. Todos responden 403 `ACCOUNT_BLOCKED`; no se crea mundo ni se invoca nada.
3. Los tres responden 403 `ACCOUNT_BLOCKED`; no sale ningún SMS, ni siquiera después de borrar las marcas de sesión.
4. Responden 200: la pantalla se escribe en el idioma de la cuenta y el cierre de sesión termina.
5. 403 `ACCOUNT_BLOCKED`: la marca gana sobre la de automatización.
6. El usuario vuelve a estar habilitado, la marca desaparece y todo responde como antes; el celular verificado y la marca de automatización siguen.
7. Ningún cambio, con un error claro.
